# 项目规则

## 分支与工作流

- `main` 分支仅用于跟踪上游仓库 `seakee/CPA-Manager`，禁止直接提交或合并自定义修改。
- 上游更新后必须尽快同步到 `main`，并立即将 `main` 合并到 `custom`，以减少冲突。
- 所有自定义功能的开发都必须从 `custom` 分支创建特性分支，完成后合并回 `custom`。禁止从 `main` 分支直接创建特性分支来开发定制功能。
- 如果开发的功能是通用且与定制无关，并准备向上游提 PR，才可以从 `main` 分支创建独立的特性分支，但需确保该分支不包含任何定制内容。
- Pull Request 的目标分支统一为 `custom`（除非是向上游提 PR）。
- 自定义改动完成后应通过 Pull Request 提交，由用户在 PR 中审计确认后再合并。

## 代码组织与侵入最小化

- 所有自定义功能应尽量使用配置化、新增文件、装饰器/扩展点等方式实现，避免侵入式修改原有文件。
- 自定义变量、函数、CSS 类名必须使用统一前缀（如 `custom_`）。
- 硬编码常量（如 `MAX_SHOW_ALL_THRESHOLD`）必须改为从配置文件读取，配置项路径统一为 `custom.quota.xxx`。
- 每添加一项定制，必须同步更新 `CUSTOM.md`，记录修改范围、用途、是否可向上游贡献等。

## 版本与发布

- 自定义版本号格式为 `v<上游版本号>-custom-<递增数字>`，例如 `v1.2.55-custom-1`。
- `custom` 分支发生更新时自动创建下一个自定义版本标签，格式为 `v<最新上游版本号>-custom-<递增数字>`。
- 仅推送上述格式的标签时触发自动构建与 Release 发布。

## 操作要求

- 以后在本项目中的每一次操作，都必须先阅读本规则文件并自觉遵守。
